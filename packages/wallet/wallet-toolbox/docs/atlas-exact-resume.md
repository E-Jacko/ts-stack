# ATLAS #520: exact signed action retry

Based on npm's @bsv/wallet-toolbox 2.10.2 SLSA-attested source e0838bc37ccaa2f13b8977bc409f437f611b0987. Maintained source branch: Quaakee/ts-stack codex/520-exact-signed-resume. Artifact identity is @bsv/wallet-toolbox@2.10.2-atlas.520.1, distributed as an immutable tarball, not published to the upstream npm namespace.

Public API remains createAction({description, options:{sendWith:[originalTxid]}}). A failed/invalid signed action can requeue only the original rawTx/inputBEEF after transaction verification, one owned outgoing transaction/notification correlation, stored output checks and input reservation conflict checks. Request, action, and input/output bookkeeping change in one storage transaction. Database write locks are acquired before snapshot reads. Ambiguous or conflicting lineage throws; callers retain the original action and must not construct a replacement.

The durable request history marks this exact retry. Subsequent broadcast failures are indeterminate (existing serviceError/sending review results) unless the exact txid is positively accepted or reported known/mined. Known/mined only returns unproven; the existing validated proof path owns completed status. A failed service response, unknown status, timeout, abort success or local failure label is never proof of retirement. No new terminal witness API is provided. listFailedActions(true) is not used and its legacy convenience behavior is not repaired here.

The generic failed request path reconstructs input reservations only when no later action owns them. It refuses ambiguous multi-user/shared request notification lineage. Existing WalletInterface and request wire formats remain unchanged; retry history is internal. No wallet identity, grant set, envelope semantics or application mint flag changes.

Regression runner: test/atlas/exact-resume.cjs, executed using tsx against source, and with imports rewritten to the exact packed package for clean-consumer qualification. Tests own SQLite databases and MockServices chains; no external network, wallet, provider, funds or credential store is accessed. SQLite concurrency/restart is exercised; MySQL runtime concurrency is not qualified by these tests. The source build is additionally checked independently against the package's original SDK dependency and adoption SDK artifact.
